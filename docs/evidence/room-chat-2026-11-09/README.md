The room-chat client is implemented and packaged as `artifacts/android/Fav-Music-room-chat-arm64.apk` (34,158,154 bytes). It preserves the installed signing identity, Android package, Expo SDK 52 runtime, and canonical Hermes registration. The previous tested APK remains at `artifacts/android/Fav-Music-arm64.apk`.

Profile and Listening rooms show the complete selectable Fav Music User ID. Native sharing includes that ID without credentials or email. A host can enter a friend's full ID; invalid, self, offline, and non-host invitation attempts are blocked. Received invitations now appear in the room-discovery UI, accept a private-room passcode, and remain pending until the server confirms joining. Invitations are bounded, deduplicated, and cleared when the account disconnects. Both users should open Listening rooms to receive realtime invitations.

Room playback starts as a small card with inline song search. The search uses the existing catalog, debounce, cache, and bounded request queue. It displays up to three distinct recordings. Queue success is shown only after a server queue update, and failed confirmation preserves the search for retry. Adding a song does not issue a racing Play command or bypass controller authority. Expanded controls mount only when requested.

Chat typing signals are coalesced to at most one pulse per 1.5 seconds with an idle stop. Disconnected sending preserves the draft, message length matches the server's 1,000-character limit, and new messages do not force users away from older messages they are reading. Account changes close the previous room socket; private-room reconnection retains the passcode in memory.

The genuine Android HTTP transport now supports GET without writing a body. Existing POST calls retain their native interface. Both methods retain HTTPS validation, forbidden redirects, bounded responses, cancellation, and the existing tunnel IPv4 behavior. The native Java harness in this folder checks GET, POST, bearer handling, endpoint rejection, and redirect rejection using an in-memory connection.

Validation: 1,128 tests passed with three existing connectivity skips; TypeScript checks passed for all four workspaces; signed ARM64 release compilation passed; APK inspection found the new GET method and native Google/audio modules, with no private environment/signing files or scanned backend secrets. Hermes still contains two `registerComponent` declarations.

Live device room verification is pending. The configured public tunnel returns NXDOMAIN (public DNS status 3, zero answers). The existing local server returns HTTP 500 for the room list and health/liveness REST routes, while GraphQL introspection and the Socket.IO handshake return HTTP 200. PostgreSQL/Redis service ports respond, so a database restart is not established as the remedy. Backend repair and one replacement HTTPS tunnel require the user's authorization under AGENTS.md §7.2; no backend source, schema, or connection-setting changes were made in this client work.
